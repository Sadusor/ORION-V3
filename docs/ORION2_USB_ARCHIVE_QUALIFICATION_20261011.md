# ORION2 disposable PC ↔ Android USB archive qualification

Candidate, **not activated**. ORION2's existing qualification Activity has an opt-in `usb_sync_qualification` branch. It creates its own `orion2_usb_sync_qualification.db` file and rejects a repeat if that file already exists. The application ID guard prohibits invocation outside `com.sadusor.orionv3.archivequal`. The normal ORION production networking and Update button are unchanged.

`tests/orion2_usb_archive_server_v1.py` runs a short-lived HTTP server on loopback `127.0.0.1:18765`, with a fresh empty temporary root and independently generated device and owner test credentials. TheHands establishes `adb reverse tcp:18765 tcp:18765` only if unoccupied, passes the disposable device secret to the ORION2 qualification Activity and collects `ORION2_USB_QUAL` logcat evidence. First Android sync writes test conversation to the temp archive; the server performs an independently owner-authorized delete; second Android sync returns its tombstone; Android applies the tombstone, replays stale local history, then reopens its own SQLite database to check no resurrection. TheHands removes its reverse mapping and stops the temporary server in a finally block. The PC test store is deleted afterward. No production service or database is modified.

Qualification checks must require `SYNC_PASS`, `DELETE_REPLAY_PASS`, and the distinct final `ORION2_USB_QUAL: PASS`, plus all previous tests and APK identity checks. **Do not claim PASS until live GITCHECK evidence confirms it.** The USB test makes no claim about remote over-LAN/ZeroTier transport, production credential enrollment, or the existing Update-button rollout. The test-only USB credential is passed to the isolated activity through an ADB intent and must not be used in production.
